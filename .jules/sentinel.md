## 2025-05-15 - Unsafe string interpolation in Alembic migration
**Vulnerability:** A baseline database migration file (`packages/db/migrations/versions/20260412_220800_baseline.py`) used string interpolation to dynamically build SQL queries for dropping tables in the downgrade process: `op.execute(sa.text(f"DROP TABLE IF EXISTS {table_name}"))`.
**Learning:** Constructing SQL statements using string interpolation with variables exposes the application to SQL Injection (SQLi) if the table names are somehow controlled by external inputs or corrupted. Security scanners also flag this as an insecure pattern. Alembic’s `op.drop_table` should be used instead, as it safely quotes identifiers. However, since `op.drop_table` does not have an `if_exists=True` flag, you must inspect the database first to see if the table exists before dropping it.
**Prevention:** Avoid string interpolation (`f"..."`) for dynamic SQL generation inside `op.execute()`. For DDL operations like table creation, alteration, and dropping, exclusively use Alembic's built-in schema operation methods (e.g., `op.create_table`, `op.drop_table`). When conditional operations are needed, use `sa.inspect(op.get_bind())` to query metadata before executing the DDL.
