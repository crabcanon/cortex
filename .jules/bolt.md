## 2024-05-18 - Optimize job events maximum sequence number calculation
**Learning:** In the `apps/api/src/cortex_api/services/jobs.py` file, we calculated `next_sequence` for job events by fetching up to 1000 existing events for a job using `existing_events = await uow.job_events.list_for_job(job_id, limit=1000)` and getting the sequence number from the last element. This involves fetching potentially 1000 rows into memory just to get a max value, which is inefficient. The db memory states we should use the optimized `get_max_sequence_no` method instead, avoiding loading event lists into memory and doing SQL aggregation.
**Action:** Instead of fetching the entire list into memory, implement a `get_max_sequence_no(job_id)` function using `func.max` on the database side inside `JobEventRepository` and call this directly from `apps/api/src/cortex_api/services/jobs.py`.
