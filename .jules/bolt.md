## 2024-05-24 - Efficient Next Sequence Number Calculation
**Learning:** Loading up to 1000 events into memory (`list_for_job(job_id, limit=1000)`) just to find the next `sequence_no` (`existing_events[-1].sequence_no + 1`) is highly inefficient and risks memory bloat, network overhead, and potential incorrect sequence calculation if the event count exceeds 1000. It behaves like an N+1 query problem, creating performance issues under high loads.
**Action:** When you need a max sequence number or next sequence number, implement a direct SQL aggregation query (e.g., `SELECT COALESCE(MAX(sequence_no), 0) FROM events WHERE job_id = ?`) in the repository and call it, instead of pulling the whole list into memory. I'll add `get_max_sequence_no(job_id)` to `JobEventRepository` to optimize this.
