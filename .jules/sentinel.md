## 2026-04-12 - [Refactor raw SQL execution to use Alembic schema operations for dropping tables]
**Vulnerability:** The migration file `packages/db/migrations/versions/20260412_220800_baseline.py` used `op.execute(sa.text(f"DROP TABLE IF EXISTS {table_name}"))` to drop tables during the downgrade process. This involves string interpolation for SQL execution, which can potentially be flagged as a security vulnerability (SQL injection risk), even if the table names are from a hardcoded list.
**Learning:** Alembic provides built-in schema operations like `op.drop_table` to safely handle identifier quoting and prevent SQL injection. Manual SQL execution with string interpolation should be avoided. Also, since `op.drop_table` does not support `if_exists=True`, it requires an extra step to check table existence via SQLAlchemy's inspector before dropping.
**Prevention:** Use `op.drop_table` instead of raw SQL execution for table drops in migrations. Always check table existence via `sa.inspect(bind).get_table_names()` if conditional dropping is required.
