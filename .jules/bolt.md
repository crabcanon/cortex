## 2025-05-24 - Database Query Optimization for Sequence Generation
**Learning:** Found a critical performance bottleneck in how `SequenceNo` was being generated for new `JobEvents`. The application was reading all previous job events using `list_for_job` to memory to figure out the last sequence number (`existing_events[-1].sequence_no + 1`). This is effectively an N+1-like issue causing massive memory loading and slowness as job events accumulate.
**Action:** Replaced the array-loading anti-pattern with direct SQLAlchemy aggregation (`func.coalesce(func.max(JobEventModel.sequence_no), 0)`) in a new repository method `get_max_sequence_no`. Future tasks that need maximum sequence counters should always use O(1) database aggregation functions rather than memory-loading lists.
