## YYYY-MM-DD - Avoid N+1 database queries with bulk operations

**Learning:** When inserting multiple related database entities sequentially in a loop using `await uow.repository.add(model)` (such as document tags or document chunks), we are creating an N+1 performance bottleneck. Even though SQLAlchemy supports batching, calling the repository's `add()` method in a loop causes individual inserts, flushes, and refresh operations per record. This issue arises primarily because the `add()` methods explicitly call `session.flush()` and `session.refresh()`, making each insert synchronously await round-trips to the DB. `session.add_all()` alone is not an optimization as it still runs per-record round-trips on `flush()` and `refresh()`.
**Action:** Always implement and use `add_many()` repository methods for bulk insertions. `add_many()` correctly builds a list of models, executes a single `await session.flush()`, and maps the resulting objects back without the overhead of per-record flushes or explicit `refresh()` calls.
