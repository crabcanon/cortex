## 2025-02-28 - Optimize JobEventRepository Sequence No Calculation
**Learning:** Found a memory anti-pattern where application services loaded an entire event stream (up to 1000 items) for a single job just to grab the maximum sequence number (using `[-1]`). Because `JobEventRecord` objects contain metadata, string traces, and structured dictionaries, allocating hundreds of objects in memory per event insert represents a significant memory bottleneck, especially for noisy jobs like document processing tasks.
**Action:** Introduced an SQL aggregation function `COALESCE(MAX(sequence_no), 0)` at the repository level which scales gracefully as an `O(1)` query, completely eliminating redundant object allocations across the entire app stack. Future queries requiring only single values (min/max/count) must bypass the `list()` implementations.
