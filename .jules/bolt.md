## 2024-05-24 - Avoiding N+1 Query-Like Inefficiencies in Sequence Computations
**Learning:** Found a critical performance anti-pattern where calculating the next sequence number for a job event loaded the entire list of a job's events (up to 1,000) into memory just to read the final event's `sequence_no` (e.g., `existing_events = await uow.job_events.list_for_job(job.job_id, limit=1000)` followed by `existing_events[-1]`). This creates massive memory overhead and slow response times, especially for jobs with many events.
**Action:** When calculating maximum sequence values, always use direct SQLAlchemy aggregation queries (e.g., `select(func.coalesce(func.max(Model.field), 0))`) in repository methods. This computes the max value using database-level optimized $O(1)$ calculations, avoiding loading unused records into application memory.
