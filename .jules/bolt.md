## YYYY-MM-DD - Optimizing database insertions with `add_many()`
**Learning:** During parsing, the persistence service was previously iterating through arrays of entities (tags, chunks, artifacts, parse run attempts) and adding them to the database context one by one. Calling `session.add(model)` followed by `session.flush()` and `session.refresh(model)` within a loop creates an N+1 query pattern which severely degrades performance when inserting large amounts of data for a single parse job, especially chunks. We learned that `add_many()` utilizing SQLAlchemy's `session.add_all()` operates without per-record refresh queries for bulk insertions, drastically reducing database round trips.
**Action:** When inserting multiple records, always use batch insertion methods like `add_many()` with `session.add_all()` to avoid N+1 query patterns. Wait to flush until all additions are made, and avoid `session.refresh()` unless the generated IDs are strictly necessary for immediate use downstream.
